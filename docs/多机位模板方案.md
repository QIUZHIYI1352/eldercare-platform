# 多机位共用一套动作模板

## 问题

原先序列动作模板（翻身、拍背、环抱转移）的特征向量**全部是二维图像空间的量**：
关节角用图像 x/y 计算，手的高度用「腕关节 y − 肩关节 y」，人体高度用「踝 y − 鼻 y」。
这些量都以**图像竖直方向**为参照，所以镜头一俯仰、一偏转就整体失真。

实测（几何仿真，同一动作从三个机位投影）：

| 维度 | 机位 A→C 漂移（除以模板标准差） |
|---|---|
| `body_height` | 5.71 |
| `hip_center_height` | 4.58 |
| `trunk_inclination` | 4.13 |
| `hand_height_right` | 2.61 |
| `hand_height_left` | 2.10 |
| **越界维度** | **6 / 16**，中位漂移 0.93 |

后果：**换机位后同一动作的匹配距离远超阈值，模板直接失效**，且靠调阈值救不回来——
阈值放宽到能容纳跨机位的正确动作，无关动作也会一起命中，那就是误报。

## 方案

改用 MediaPipe 提供的 **`pose_world_landmarks`**（真实米制三维坐标，原点在髋中心），
由三维量构造特征。三维关节夹角是**旋转不变量**，与相机朝向无关。

### 两个关键的语义替换

| 原特征（二维） | 新特征（三维） | 为什么 |
|---|---|---|
| `trunk_inclination` = 躯干相对**图像竖直**方向的倾角 | `trunk_vs_leg_angle` = 躯干相对**下肢**的三维夹角 | 图像竖直方向随镜头俯仰而变；身体自身的夹角不会 |
| `hand_height_*` = 腕 y − 肩 y | `l/r_wrist_height` = 腕在**躯干自洽坐标系**中的纵向分量 | 同样摆脱对图像坐标系的依赖 |

躯干自洽坐标系：原点 = 髋中心，y 轴 = 髋→肩（躯干轴），x 轴 = 骨盆横轴正交化，z = x × y。

### 刻意回避的量

`head_vs_trunk`（鼻→肩→髋夹角）实测漂移 **3.55σ**，是三维特征里唯一明显越界的维度——
单目估计中鼻子的深度最不稳。已剔除。

### 最终特征集（18 维，`FEATURE_ORDER_3D`）

```
l/r_elbow_angle      l/r_shoulder_angle    l/r_knee_angle      l/r_hip_angle
trunk_vs_leg_angle   hands_distance
l/r_wrist_to_hip     leg_extend             ankle_distance
l/r_wrist_height     l/r_wrist_forward
```

## 效果

「换机位额外增加的距离」（同动作、跨机位距离 − 同机位距离），阈值 8.0：

| 特征方案 | 换到侧后方 40° | 换到高位俯拍 |
|---|---|---|
| 现有 2D 特征 | **+45.8** | **+9.2** |
| 3D（无噪声，验证几何不变性） | 0.00 | 0.00 |
| 3D（真实量级噪声） | **+0.78** | **+0.55** |
| 3D（双倍噪声，悲观） | −0.34 | −1.96 |

**约 58 倍改善，且在双倍噪声下依然成立。**

判别力不随机位衰减：

| 特征 | 同机位可分性 | 跨机位可分性 |
|---|---|---|
| 现有 2D | 9.9x | **2.1x（失效）** |
| 3D | 4.1x | **3.9x / 3.9x** |

## 怎么用

### 1. 录制 3D 模板

```bash
python record_template.py --name "协助翻身" --space 3d --duration 6
```

覆盖已有动作时加 `--action-id act_xxx`。

### 2. 在真实机位上标定阈值

仿真给的 40.0 只是**起点**。真实阈值必须在你的机器上实测：

```bash
# 先做「正确动作」，量出真实匹配距离的水平
python calibrate_template.py --action-id act_xxx --duration 6 --label right

# 再做「无关动作」，量出误报的距离下限
python calibrate_template.py --action-id act_xxx --duration 6 --label wrong
```

两次跑完自动给出建议阈值（取正确动作上方 35% 处，留波动余量、与无关动作保持间隔），
并打印固化阈值的命令。

### 3. 切换运行时特征空间

```bash
FEATURE_SPACE=3d python run.py
```

默认仍是 `2d`，**不切换则行为与现在完全一致**。

## 安全设计：版本不符就跳过，绝不硬匹配

模板里带 `space` 与 `version` 字段。启动监控时若模板版本与运行时空间不符：

- **跳过该模板**，并在控制台打印需要重录的清单
- 15/16 维与 18 维的向量直接对比会得到无意义的距离，可能凑出"匹配成功"的假象——
  那正是误报。宁可此时不报警。

`TemplateMatcher` 构造函数对维度不符直接抛 `ValueError`，`_build_matchers`
捕获后归类为"跳过"。相关行为由 `tests/test_camera_invariance.py::test_mismatched_template_is_skipped` 锁定。

## 已验证 / 未验证

**已验证**（`tests/test_camera_invariance.py`，8 项，调用生产代码而非另写对照实现）：

- 无噪声时 3D 特征跨机位距离 **严格为 0**（几何旋转不变性）
- 3D 特征的机位损失 < 2D 的 25%
- 2D 特征换机位后距离确实恶化 > 1.5 倍（记录旧缺陷，防止回退）
- 3D 特征在三个机位下判别力均 > 3 倍
- 默认阈值 40.0 容得下跨机位的正确动作、挡得住无关动作
- 版本不符的模板被跳过

**未验证**（必须在你的实机上做）：

- 真实 MediaPipe 三维估计的误差量级。仿真里用的是**合理假设**（横向 1.2cm
  平滑抖动、深度 3cm、视角相关的仿射畸变 3%），不是实测值
- 建议阈值 40.0 的实际适用性 → **务必先跑 `calibrate_template.py`**

如果标定发现 3D 阈值下正确动作与无关动作距离太接近，说明该动作在当前机位区分度不足，
应先调整机位让动作完整入镜，而不是硬调阈值（那会牺牲"不误报"的底线）。

## 遗留

- 规则型动作（`conditions` 里的角度阈值）仍是二维量，同样受机位影响，
  本轮未改。若要彻底解决需一并迁移到三维。
- `record_template.py` 的 3D 模板若 mediapipe 不返回 `pose_world_landmarks`，
  会明确报错并建议改用 `--space 2d`，不会静默产生坏模板。
