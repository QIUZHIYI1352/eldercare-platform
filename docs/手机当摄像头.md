# 用手机当摄像头（接入本平台）

**结论：可行，零成本，不需要买设备。** 手机本质上就是一台带 WiFi 的摄像头。

> **国内应用商店搜不到 IP Webcam 是正常的**——它只上架 Google Play。
> 所以国内优先走 **A（平台内嵌，什么都不用装）** 或 **D（商店里能下到的）**。

## 四条路线

| 路线 | 手机端要装 | 电脑端要装 | 怎么接进平台 | 适用 |
|---|---|---|---|---|
| **A. 平台内嵌**（首选） | 自带浏览器，**什么都不用装** | 无（平台自带） | 页面点「用手机当摄像头」→ 扫码 | 所有手机；日常使用 |
| **B. 独立脚本** | 自带浏览器，**什么都不用装** | 无 | 填 `http://127.0.0.1:8444/video` | 不想开平台，只想试摄像头 |
| **C. 网络流 App** | IP Webcam 一类（仅 Google Play） | 不用装 | 填 `http://手机IP:8080/video` | Android，且能装 APK |
| **D. 虚拟摄像头** | iVCam / EV虚拟摄像头 | 需装厂商客户端 | 选 `1`（当作本机摄像头） | 国内商店可下；iPhone |

> **已用生产代码跑通整条链路**：模拟手机推真实视频帧 → 平台服务转发 →
> `monitor.py` 从这条流里识别出「屈膝下蹲」等动作（325 帧零失败，实测 11.5 fps）。
> 未验证的只剩「手机浏览器里的摄像头采集」这一步（需要真机点一次授权）。

## 路线 A：平台内嵌（首选）

**这是最短的一条路：两步。不用命令行、不用记地址、不用先建"设备"。**

### 1. 电脑上启动平台

```bash
python run.py
```

浏览器打开 `http://localhost:8000`，用教师/管理员账号登录，
进「实时监控」页，点 **「用手机当摄像头」**。

### 2. 手机扫码

页面上会弹出一个二维码：

- 手机与电脑必须在**同一个 WiFi**
- 用相机扫这个码，手机会打开一个 `https://192.168.x.x:8443/` 页面
- 会提示「连接不私密 / 证书无效」——自签证书的正常现象，
  点「高级」→「继续前往」。**画面只在你自己的局域网内，不经过任何服务器。**
- 页面会**自动**申请摄像头权限，点「允许」就开始推流
- **把手机横过来**（页面会提示），后置摄像头会自动启用

手机上会显示「电脑已收到 N 帧」——看到这个数字就说明整条链路是通的，
不必再跑回电脑前面确认。

### 3. 回到平台页面

弹窗里的状态会变成「手机已连接 · xx fps」。视频源地址**已经自动填好**，
直接点「开始监控」即可。

这个源同时被登记进「设备管理」，名字是**「手机摄像头」**——
以后不用再扫码，在设备下拉里直接选就行。它的在线状态是**实时**的：
手机关掉页面、锁屏或走出 WiFi，列表里立刻变「离线」。

### 端口与防火墙

平台会额外开两个端口，分工是刻意的：

| 端口 | 绑在哪 | 用途 |
|---|---|---|
| 8443（HTTPS） | `0.0.0.0` | 手机扫码后访问的页面，**需要对局域网开放** |
| 8444（HTTP） | `127.0.0.1` | 平台自己读画面的 MJPEG，**只给本机，不对局域网暴露画面** |

首次运行 Windows 会弹一次防火墙授权（只为 8443）。
若 8443 已被占用（比如独立脚本还开着），平台会**自动往后找一个空闲端口**，
不需要手动处理。

### 为什么必须是 https，能不能省掉

不能。浏览器**只在安全上下文下**允许网页访问摄像头，`http://192.168.x.x`
会被直接拒绝。所以用了自签证书；代价只是手机上点一次「继续前往」。

### 那个「证书不受信任」告警为什么每次都弹，怎么少弹几次

**先说结论：这不是配置错了，是自签方案的固有代价。** 浏览器只信任正式 CA
签发的证书，而局域网 IP 根本申请不到正式证书（CA 不给私有地址签发），
所以只能自签，浏览器就一律不认。

"每次都弹"的原因：浏览器只把"继续前往"记在**本次会话**里，关掉页面、
换浏览器、手机重启之后会再来一次。证书本身是长期有效的（10 年，且地址没变就复用），
只是浏览器的例外记录不长期保存。

三个办法，按省事程度排：

| 办法 | 效果 | 代价 |
|---|---|---|
| 用**系统相机或浏览器**扫码，别用微信扫 | 少一层拦截（微信内置浏览器会再加一道更啰嗦的提示） | 无 |
| 把这张证书装进手机，当受信任的根证书 | **彻底不弹** | 一次性操作；见下方说明 |
| 给平台配域名 + 正式证书（`部署指南.md` 有 Nginx + Certbot 那节） | 彻底不弹，手机还能用 4G 连 | 要域名、国内要备案、要配 Nginx |

**把证书装进手机（推荐，一劳永逸）**

证书文件在 `.workbuddy/phone_cam_cert.pem`（首次运行手机摄像头时自动生成）。

Android：

1. 把这个文件传到手机（微信/QQ 传给自己都行），**改后缀成 `.crt`**
2. 设置 → 安全 → 加密与凭据 → 安装证书 → **CA 证书** → 选择该文件
3. 之后访问 `https://<电脑IP>:8443/` 不再告警

iOS：

1. 传到手机（AirDrop 或邮件附件），存到「文件」
2. 设置 → 已下载描述文件 → 安装
3. 设置 → 通用 → 关于本机 → **证书信任设置** → 打开该证书的完全信任

> ⚠️ 想清楚再装：装成根证书等于让"持有这张证书私钥的人"可以对这台手机
> 冒充任意网站。私钥就在这台电脑上（`.workbuddy/phone_cam_key.pem`）。
> 只在你自己完全可控的环境里这么做；公用的手机不要装。

## 路线 B：独立脚本（不开平台时用）

和路线 A **共用同一份实现**（`backend/vision/phone_cam.py`），
适合只想快速验证摄像头通不通、不想启动平台的场合。

```bash
python phone_cam.py
```

它会打印地址，并在终端里**画一个二维码**（终端背景色会影响识别，
扫不动就直接手输打印出来的地址）。手机上的步骤和路线 A 完全一样。

电脑侧接：

```bash
python check_source.py --source http://127.0.0.1:8444/video   # 先体检
python monitor.py     --source http://127.0.0.1:8444/video   # 再接入
```

可调参数：

```bash
python phone_cam.py --fps 20 --target 1280x720 --port 8443
```

- `--fps`：手机推帧帧率上限，默认 15。
  **低于 12 会让「持续时长」类判定失准**，WiFi 好可以调到 20。
- `--target`：输出画面尺寸，默认 `1280x720`。不是 16:9 会给出警告。

> 页面里做了「上一帧没发完就跳过」的保护，网络慢时不会堆积请求导致越用越卡。

## 路线 C：网络流 App（Android，需 APK 直装）

### 1. 手机端

1. 装 **IP Webcam**（**只在 Google Play**，国内需自行找官方 APK 直装）
2. **用后置摄像头**（重要，原因见下「必须避开的坑」）
3. 设置里锁定：分辨率选 **1280×720**、方向锁定**横屏**、关闭自动对焦以外的自动功能
4. 拉到页面底部 → **「启动服务器」**
5. 记下屏幕上显示的地址，形如：

   ```
   http://192.168.1.23:8080
   ```

   串流地址就是它加 `/video`：

   ```
   http://192.168.1.23:8080/video
   ```

   （有的版本是 `/videofeed`，以 App 页面上的链接为准）

### 2. 电脑端：先体检，再接入

**不要直接接到「监控设备」里就开始跑**，先跑一遍体检——视频源的坑几乎都是静默的
（能打开但只有 3fps、姿态检出率只有 40%、宽高比和录模板时不一致），
在网页上只表现为「识别不准」，很难反查根因：

```bash
python check_source.py --source http://192.168.1.23:8080/video
```

它会报告：打开耗时、分辨率与宽高比、实测帧率、帧间隔抖动、姿态检出率、平均可见度，
并**与库里已有的序列模板比对宽高比**，最后给出结论和下一步命令。

体检通过后：

```bash
# 命令行直接跑
python monitor.py --source http://192.168.1.23:8080/video

# 或在网页「监控设备」里新建设备，url 字段填同一地址，之后在「实时监管」里选它
```

### 3. 前置条件（不满足就连不上）

- 手机与电脑在**同一个 WiFi / 局域网**
- 路由器**没有开启「AP 隔离 / 客户端隔离」**（这个开关会让同网段设备互相看不见，最常见的原因）
- 手机串流已启动，且**屏幕保持常亮**（很多手机息屏后会停掉串流服务）
- 建议把电脑防火墙对本程序放行

## 路线 D：虚拟摄像头（国内商店可下）

手机与电脑各装一个客户端，手机就被系统识别成一台普通摄像头。

1. 手机装 App，电脑装对应客户端
2. 同一 WiFi 或 USB 连接
3. 连上后电脑会多出一个摄像头设备 → 平台按**索引**接入：

   ```bash
   python check_source.py --source 1     # 索引逐个试，0 通常是笔记本内置摄像头
   python monitor.py --source 1
   ```

国内可下的几款（按适配程度排序）：

| 软件 | 免费版画质 | 支持 | 备注 |
|---|---|---|---|
| **iVCam**（e2eSoft，国产） | 1080p | iOS + Android | 国内商店/官网可下；iPhone 兼容性最好 |
| **EV虚拟摄像头**（一维科技） | 高清 | iOS + Android | 官网 ieway.cn 直接下 APK/ipa |
| **DroidCam** | **仅 480p** | Android 为主 | 免费版只有 480p（640×480 = 4:3），
  与 16:9 模板**宽高比不符**，本平台不建议用免费版 |
| **Iriun Webcam** | 1080p | iOS + Android | 跨平台好，功能基础 |

⚠️ 选虚拟摄像头路线时务必注意两点：

- **它会替你决定分辨率与宽高比**，可能和你录模板时不一致
  （上表 DroidCam 免费版就是 4:3）。**接入前一定先跑 `check_source.py` 看宽高比**。
- 有的虚拟摄像头驱动会固定输出某个尺寸，而你无法改——遇到这种情况就换路线 A。

> iPhone 用这条路线最省事（iOS 上缺少像 IP Webcam 那样直接给 URL 的免费方案）。

## 必须避开的坑

### 1. 宽高比必须与录模板时一致 ⚠️ 最重要

`2d` 空间（默认）的关节角是用**归一化坐标**算的，而 mediapipe 的归一化是
`x/W`、`y/H` —— **两个不同的分母**。所以画面比例一变，角度就系统性偏移。
实测（同一物理姿态）：

| 画面 | 躯干角 | 膝关节角 | 相对 16:9 最大偏差 |
|---|---|---|---|
| 16:9 1280×720 | 6.82° | 171.43° | — |
| 4:3 960×720 | 9.06° | 168.64° | 2.79° |
| **9:16 竖屏** | **20.70°** | **154.53°** | **16.90°** |
| 16:9 1920×1080 | 6.82° | 171.43° | 0.00° |

要点：

- **只有比例有关，分辨率无关**（同为 16:9 时 720p 与 1080p 完全一致，
  所以「换个更高清的摄像头」本身无害）。
- **竖屏代价极大**：躯干角 6.8° 变 20.7°，等于把站立判成前倾；
  膝关节角 171° 变 154°，等于虚报了一个屈膝动作。**手机必须横屏**。
- 因此：**录模板和运行时用同一宽高比**，否则改用三维机位无关特征：

  ```bash
  python record_template.py --name "协助翻身" --space 3d --source http://手机IP:8080/video
  FEATURE_SPACE=3d python monitor.py --source http://手机IP:8080/video
  ```

  `3d` 空间用米制三维坐标，**不受宽高比影响**，同时也不受机位影响——
  手机场景本来就容易挪动，建议直接用 `3d`。
- 录模板时会把当时的画面尺寸写进模板（`frame_size` / `frame_aspect`），
  `check_source.py` 会拿它和你当前的源比对，不一致会直接报出来。

### 2. 机位必须固定

模板匹配对**画面几何**极敏感，手机挪一次模板就可能全废。所以：

- 用手机支架/三脚架固定，别手持
- **关掉自动旋转**（横竖屏切换等于换了一个宽高比）
- **关掉电子防抖（EIS）**：它会裁切画面，等于改变了有效视野与比例
- 关掉「自动切换镜头」「移动侦测」这类会改变画面的功能
- 手机发热后有些机型会自动降帧 → 尽量插着电跑，并让 `check_source.py` 复测帧率

### 3. 用后置摄像头

前置摄像头普遍带**美颜/瘦脸/磨皮**，那是对画面做人脸/人体形变——
会直接扭曲骨架关键点，属于**算法层面无法修正**的误差。后置摄像头一般不做这些处理。

## 故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 打不开 / 超时 | 不在同一网段，或路由器开了 AP 隔离 | 关掉 AP 隔离；用手机浏览器访问电脑的 `http://电脑IP:8000` 反向验证连通性 |
| 能打开但帧率 < 10 | WiFi 信号弱 / App 省电策略 / 手机息屏 | 靠近路由器；关省电；屏幕常亮；优先 5GHz |
| 姿态检出率低 | 没拍到全身、逆光、离太远 | 让全身（含脚）入镜；避免背后强光；`check_source.py` 会报「平均可见度」 |
| 中途卡住不动 | 手机端串流被系统挂起 | 平台会自动重连（`VideoSource` 对 `http://` 是断流重连语义，不是读完结束） |
| 识别忽好忽坏 | 分辨率中途变化 / 手机被移动 | `check_source.py` 会检测「采集期间分辨率变化」并报为不可用 |
| 角度整体偏大或偏小 | 宽高比与录模板时不一致 | 统一为横屏同比例，或改用 `--space 3d` |
| 路线 A / B：手机提示「连接不私密」 | 自签证书 | 正常，点「高级 → 继续前往」即可；**不要去信任它**，忽略一次就够 |
| 路线 A / B：页面没有画面 | 摄像头权限被拒 / 用了 http 打开 | 确认地址是 `https://` 开头；再点一次页面上那个按钮（自动授权可能被浏览器拦下） |
| 路线 A / B：手机上打不开这个网址 | 不在同一 WiFi / AP 隔离 / 没放行 8443 | 见上一行「打不开 / 超时」；Windows 防火墙要放行 8443（首次运行会弹窗） |
| 路线 A / B：能连上一会儿就断 | 手机锁屏 / 浏览器切到后台 | 页面已申请屏幕常亮（wakeLock），但仍建议关掉系统自动锁屏并保持前台 |
| 设备列表里「手机摄像头」是离线 | 手机没在推流 | 状态是实时的：手机重新连上就会变「在线」。没推流时显示离线是**正确**行为，不是故障 |

## 相关工具

- **`backend/vision/phone_cam.py`**：路线 A / B 共用的服务端实现。手机只用浏览器，无需装任何 App
- **`backend/qr.py`**：把手机要打开的地址转成二维码（复用 OpenCV 的编码器，零额外依赖）
- **`backend/routers/phone_cam.py`**：平台的 `/api/phone-cam/*` 接口，负责启停服务与登记设备
- **`phone_cam.py`**：路线 B 的命令行入口（同一份实现的薄封装）
- `check_source.py`：接入前体检任意视频源（摄像头 / RTSP / HTTP / 文件）
- `calibrate_rule.py` / `calibrate_template.py`：阈值标定，可直接在手机流上跑
  （`--source <手机流地址>`）
- `record_template.py`：录制序列模板
