# 用手机当摄像头（接入本平台）

**结论：可行，零成本，不需要买设备。** 手机本质上就是一台带 WiFi 的摄像头。

> **国内应用商店搜不到 IP Webcam 是正常的**——它只上架 Google Play。
> 所以国内优先走 **A（什么都不用装）** 或 **C（商店里能下到的）**。

## 三条路线

| 路线 | 手机端要装 | 电脑端要装 | 平台接入方式 | 适用 |
|---|---|---|---|---|
| **A. 手机浏览器**（首选） | 自带浏览器，**什么都不用装** | 跑一条本项目自带的命令 | `--source http://127.0.0.1:8444/video` | 所有手机；商店没 App 时 |
| **B. 网络流 App** | IP Webcam 一类（仅 Google Play） | 不用装 | `--source http://手机IP:8080/video` | Android，且能装 APK |
| **C. 虚拟摄像头** | iVCam / EV虚拟摄像头 | 需装厂商客户端 | `--source 1`（当作本机摄像头） | 国内商店可下；iPhone |

> **已验证整条链路**：用本地服务模拟手机推帧，`monitor.py` 成功从这条流里
> 识别出「屈膝下蹲 / 双臂抬起 / 双手靠近」等动作，姿态检出率 100%，
> 画面为 1280×720（16:9）。
> 未用真机验证的部分只剩「手机浏览器里的摄像头采集」这一步
> （需要手机点一次授权），其余全部走的是生产代码。

## 路线 A：手机浏览器（首选，零安装）

这条路线不需要任何 App，也不需要电脑上装虚拟摄像头客户端。

### 1. 电脑上启动服务

```bash
python phone_cam.py
```

它会打印两样东西：

```
① 手机浏览器打开：  https://10.220.63.201:8443/     ← 在手机上打开这个
② 电脑上用这个地址：python monitor.py --source http://127.0.0.1:8444/video
```

首次运行会自动生成一张自签证书（存在 `.workbuddy/`，之后复用）。

### 2. 手机上打开那个 https 地址

- 手机与电脑必须在**同一个 WiFi**
- 会提示「连接不私密 / 证书无效」——自签证书的正常现象，
  点「高级」→「继续前往」。**画面只在你自己的局域网内，不经过任何服务器。**
- 点页面上的绿色按钮，允许摄像头权限
- **把手机横过来**（页面会提示），后置摄像头会自动启用

### 3. 电脑上体检，然后接入

```bash
python check_source.py --source http://127.0.0.1:8444/video   # 先看帧率与检出率
python monitor.py     --source http://127.0.0.1:8444/video   # 再接入
```

### 为什么是 https，能不能省掉

不能。浏览器**只在安全上下文下**允许网页访问摄像头，`http://192.168.x.x`
会被直接拒绝。所以用了自签证书；代价只是手机上点一次「继续前往」。

### 可调参数

```bash
python phone_cam.py --fps 20 --target 1280x720 --port 8443
```

- `--fps`：手机推帧帧率上限，默认 15。
  **低于 12 会让「持续时长」类判定失准**，WiFi 好可以调到 20。
- `--target`：输出画面尺寸，默认 `1280x720`。
  必须是 16:9，且**与录模板时一致**（原因见下「必须避开的坑」）。

> 页面里做了「上一帧没发完就跳过」的保护，网络慢时不会堆积请求导致越用越卡。

## 路线 B：网络流 App（Android，需 APK 直装）

### 1. 手机端

1. 装 **IP Webcam**（**只在 Google Play**，国内需自行找官方 APK 直装）
2. **用后置摄像头**（重要，原因见下「必须避开的坑」）
3. 设置里锁定：分辨率选 **1280×720**、方向锁定**横屏**、关闭自动对焦以外的自动功能
4. 拉到页面底部 → **「启动服务器」**
5. 记下屏幕上显示的地址，形如：

   ```
   http://192.168.1.23:8080
   ```

   串流地址就是它加 `/video`：

   ```
   http://192.168.1.23:8080/video
   ```

   （有的版本是 `/videofeed`，以 App 页面上的链接为准）

### 2. 电脑端：先体检，再接入

**不要直接接到「监控设备」里就开始跑**，先跑一遍体检——视频源的坑几乎都是静默的
（能打开但只有 3fps、姿态检出率只有 40%、宽高比和录模板时不一致），
在网页上只表现为「识别不准」，很难反查根因：

```bash
python check_source.py --source http://192.168.1.23:8080/video
```

它会报告：打开耗时、分辨率与宽高比、实测帧率、帧间隔抖动、姿态检出率、平均可见度，
并**与库里已有的序列模板比对宽高比**，最后给出结论和下一步命令。

体检通过后：

```bash
# 命令行直接跑
python monitor.py --source http://192.168.1.23:8080/video

# 或在网页「监控设备」里新建设备，url 字段填同一地址，之后在「实时监管」里选它
```

### 3. 前置条件（不满足就连不上）

- 手机与电脑在**同一个 WiFi / 局域网**
- 路由器**没有开启「AP 隔离 / 客户端隔离」**（这个开关会让同网段设备互相看不见，最常见的原因）
- 手机串流已启动，且**屏幕保持常亮**（很多手机息屏后会停掉串流服务）
- 建议把电脑防火墙对本程序放行

## 路线 C：虚拟摄像头（国内商店可下）

手机与电脑各装一个客户端，手机就被系统识别成一台普通摄像头。

1. 手机装 App，电脑装对应客户端
2. 同一 WiFi 或 USB 连接
3. 连上后电脑会多出一个摄像头设备 → 平台按**索引**接入：

   ```bash
   python check_source.py --source 1     # 索引逐个试，0 通常是笔记本内置摄像头
   python monitor.py --source 1
   ```

国内可下的几款（按适配程度排序）：

| 软件 | 免费版画质 | 支持 | 备注 |
|---|---|---|---|
| **iVCam**（e2eSoft，国产） | 1080p | iOS + Android | 国内商店/官网可下；iPhone 兼容性最好 |
| **EV虚拟摄像头**（一维科技） | 高清 | iOS + Android | 官网 ieway.cn 直接下 APK/ipa |
| **DroidCam** | **仅 480p** | Android 为主 | 免费版只有 480p（640×480 = 4:3），
  与 16:9 模板**宽高比不符**，本平台不建议用免费版 |
| **Iriun Webcam** | 1080p | iOS + Android | 跨平台好，功能基础 |

⚠️ 选虚拟摄像头路线时务必注意两点：

- **它会替你决定分辨率与宽高比**，可能和你录模板时不一致
  （上表 DroidCam 免费版就是 4:3）。**接入前一定先跑 `check_source.py` 看宽高比**。
- 有的虚拟摄像头驱动会固定输出某个尺寸，而你无法改——遇到这种情况就换路线 A。

> iPhone 用这条路线最省事（iOS 上缺少像 IP Webcam 那样直接给 URL 的免费方案）。

## 必须避开的坑

### 1. 宽高比必须与录模板时一致 ⚠️ 最重要

`2d` 空间（默认）的关节角是用**归一化坐标**算的，而 mediapipe 的归一化是
`x/W`、`y/H` —— **两个不同的分母**。所以画面比例一变，角度就系统性偏移。
实测（同一物理姿态）：

| 画面 | 躯干角 | 膝关节角 | 相对 16:9 最大偏差 |
|---|---|---|---|
| 16:9 1280×720 | 6.82° | 171.43° | — |
| 4:3 960×720 | 9.06° | 168.64° | 2.79° |
| **9:16 竖屏** | **20.70°** | **154.53°** | **16.90°** |
| 16:9 1920×1080 | 6.82° | 171.43° | 0.00° |

要点：

- **只有比例有关，分辨率无关**（同为 16:9 时 720p 与 1080p 完全一致，
  所以「换个更高清的摄像头」本身无害）。
- **竖屏代价极大**：躯干角 6.8° 变 20.7°，等于把站立判成前倾；
  膝关节角 171° 变 154°，等于虚报了一个屈膝动作。**手机必须横屏**。
- 因此：**录模板和运行时用同一宽高比**，否则改用三维机位无关特征：

  ```bash
  python record_template.py --name "协助翻身" --space 3d --source http://手机IP:8080/video
  FEATURE_SPACE=3d python monitor.py --source http://手机IP:8080/video
  ```

  `3d` 空间用米制三维坐标，**不受宽高比影响**，同时也不受机位影响——
  手机场景本来就容易挪动，建议直接用 `3d`。
- 录模板时会把当时的画面尺寸写进模板（`frame_size` / `frame_aspect`），
  `check_source.py` 会拿它和你当前的源比对，不一致会直接报出来。

### 2. 机位必须固定

模板匹配对**画面几何**极敏感，手机挪一次模板就可能全废。所以：

- 用手机支架/三脚架固定，别手持
- **关掉自动旋转**（横竖屏切换等于换了一个宽高比）
- **关掉电子防抖（EIS）**：它会裁切画面，等于改变了有效视野与比例
- 关掉「自动切换镜头」「移动侦测」这类会改变画面的功能
- 手机发热后有些机型会自动降帧 → 尽量插着电跑，并让 `check_source.py` 复测帧率

### 3. 用后置摄像头

前置摄像头普遍带**美颜/瘦脸/磨皮**，那是对画面做人脸/人体形变——
会直接扭曲骨架关键点，属于**算法层面无法修正**的误差。后置摄像头一般不做这些处理。

## 故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 打不开 / 超时 | 不在同一网段，或路由器开了 AP 隔离 | 关掉 AP 隔离；用手机浏览器访问电脑的 `http://电脑IP:8000` 反向验证连通性 |
| 能打开但帧率 < 10 | WiFi 信号弱 / App 省电策略 / 手机息屏 | 靠近路由器；关省电；屏幕常亮；优先 5GHz |
| 姿态检出率低 | 没拍到全身、逆光、离太远 | 让全身（含脚）入镜；避免背后强光；`check_source.py` 会报「平均可见度」 |
| 中途卡住不动 | 手机端串流被系统挂起 | 平台会自动重连（`VideoSource` 对 `http://` 是断流重连语义，不是读完结束） |
| 识别忽好忽坏 | 分辨率中途变化 / 手机被移动 | `check_source.py` 会检测「采集期间分辨率变化」并报为不可用 |
| 角度整体偏大或偏小 | 宽高比与录模板时不一致 | 统一为横屏同比例，或改用 `--space 3d` |
| 路线 A：手机提示「连接不私密」 | 自签证书 | 正常，点「高级 → 继续前往」即可；**不要去信任它**，忽略一次就够 |
| 路线 A：页面点按钮后没画面 | 摄像头权限被拒 / 用了 http 打开 | 确认地址是 `https://` 开头；在浏览器设置里给该站点摄像头权限 |
| 路线 A：手机上打不开这个网址 | 不在同一 WiFi / AP 隔离 | 见上一行「打不开 / 超时」；也可让手机先访问 `http://电脑IP:8000` 试连通性 |
| 路线 A：能连上一会儿就断 | 手机锁屏 / 浏览器切到后台 | 浏览器切后台会被系统挂起，保持页面在前台并关掉自动锁屏 |

## 相关工具

- **`phone_cam.py`**：路线 A 的服务端。手机只用浏览器，无需装任何 App
- `check_source.py`：接入前体检任意视频源（摄像头 / RTSP / HTTP / 文件）
- `calibrate_rule.py` / `calibrate_template.py`：阈值标定，可直接在手机流上跑
  （`--source <手机流地址>`）
- `record_template.py`：录制序列模板
